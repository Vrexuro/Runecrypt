# Runecrypt 3D Bisa Dimainkan: Rencana Implementasi

> **Untuk agen pelaksana:** WAJIB memakai sub-skill superpowers:subagent-driven-development atau superpowers:executing-plans (Native, seperti M2) untuk mengerjakan rencana ini task demi task. Setiap langkah memakai checkbox (`- [ ]`).

**Tujuan:** Satu arena 3D yang bisa dimainkan: Pyromancer 3D bergerak, membidik, dan menembakkan bola api bercahaya ke gelombang Tulang Penjaga 3D, dengan aturan cahaya dari `Runecrypt.Core`.

**Arsitektur:**
- **Assembly baru `Runecrypt.Game3D`** (`Assets/Runecrypt3D/Scripts/`) berisi komponen 3D. Assembly ini mereferensikan `Runecrypt.Core` untuk logika, dan `Runecrypt.Game` hanya untuk wrapper input `RunecryptControls`.
- **Pemetaan bidang:** bidang permainan 2D `Vector2(x, y)` dipetakan ke lantai `Vector3(x, 0, y)` lewat `Plane3D`.
- **Cahaya:** `LightField` dari Core dipakai apa adanya. Pemeriksaan dinding memakai `Physics.Linecast` setinggi pinggang.
- **Arena dibangun builder editor**, mengikuti pola `M1Builder`, supaya bisa direproduksi.

**Teknologi:** Unity 6000.3.26f1, URP 17.3 dengan Universal Renderer (Forward+), fisika 3D bawaan, Input System, Unity Test Framework, Blender 5.3 lewat jembatan MCP Unity (`blender_bridge`), Python 3.12 dengan Pillow untuk lembar referensi.

**Spec:** `Docs/specs/2026-11-20-3d-playable-design.md`. Aturan cahaya: `Docs/GDD.md` §5.5. Angka pemain: GDD §4.1.

## Review Focus
1. **Bidikan mouse saat kursor di luar lantai** (misalnya di atas UI atau ke langit). Sinar dari kamera yang tidak mengenai bidang lantai tidak boleh menghasilkan NaN. Arah bidik terakhir dipakai (Task 2).
2. **Cahaya menembus dinding.** Musuh di balik pilar tidak boleh Tersingkap oleh cahaya pemain di sisi lain (Task 2).
3. **Bola api cepat menembus dinding atau musuh** di antara dua langkah fisika (Task 3).
4. **Pemain atau musuh terdorong keluar lantai atau naik ke atas musuh lain.** Sumbu Y dan rotasi rigidbody harus dikunci (Task 3, Task 4).
5. **Terlalu banyak lampu titik** saat banyak bola api. Forward biasa membatasi 8 lampu per objek, jadi renderer memakai Forward+ (Task 1).

```csharp
public class Player3D : MonoBehaviour, IDamageable
{
    public static Player3D Instance { get; }
    public Health Health { get; }            // Core.Health(6)

{
    public void Launch(Vector2 dir);          // damage 3, kecepatan 12, jangkauan 7; tinggi terbang 0,5

```

**Perilaku:**
- `Player3D` memakai Rigidbody dengan constraint FreezePositionY dan FreezeRotation (Review Focus 4). Kecepatan 4 tile/detik, sama seperti 2D.
- Bidik: `Plane3D.RayToFloor(cam.ScreenPointToRay(AimPoint))` diteruskan ke `AimSelector.Select`. Kalau sinar tidak mengenai lantai, arah bidik terakhir dipakai.
- Tubuh pemain menghadap arah bidik, dan cahaya pemain memakai `LightSource3D` dengan radius 3.
- `Fireball3D` menyimpan Point Light dan `LightSource3D`. Setiap `FixedUpdate`, ia melakukan `SphereCast` sepanjang langkah terhadap Walls dan Enemies (Review Focus 3). Kalau mengenai `IDamageable`, ia memanggil `TakeHit(new HitInfo(3, Fire, true, ToPlane(pos)))` lalu hilang. Kalau mengenai dinding, ia hilang. Lewat 7 tile, ia juga hilang.

**Test:**

- [ ] `Fireball3D_StopsAtWall`: dinding 2 tile di depan dan musuh 4 tile di depan, maka musuh tidak kena.
- [ ] `Fireball3D_FastShotDoesNotTunnel`: kecepatan 60, dinding tipis 0,2 di depan, maka bola api tetap berhenti.
